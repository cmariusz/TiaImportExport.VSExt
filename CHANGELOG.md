# Change Log

All notable changes to the **CMsoft Import for TiaPortal** extension (formerly TIA Portal Import) are documented in this file.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.0.0/) and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

---

## [4.6.0] - 2026-11-04

### Added

- **PROFINET networks from a network file** (PRO) — a `*.network.json` file describes PROFINET devices with their modules and I/O addresses, IP addresses, PROFINET device names and numbers, the IO system, the port interconnections (topology) and the MRP roles — for example generated by a script from an Excel list. Right-click the file in the Explorer, **Export to TIA Portal: Network File**: the extension checks the file, lists what it will change in the project and, after you confirm, writes only the differences. A failure leaves TIA Portal as it was, and one **Edit > Undo** in TIA Portal takes the whole import back. A PLC or an HMI is never deleted or replaced, only its network settings change. **Import Network File** (the **…** menu of the **Project** view) writes the network of the project to `Devices/Network/<project>.network.json`. Unlike the CAx (AML) import of TIA Portal, the network file keeps the MRP roles and the device numbers.
- **AI tools and network files** — `tia_import_hw_config` and `tia_import_file` import a network file and `tia_export_hw_config` with `format: "network"` writes one, so an agent or a script can generate a network and bring it into TIA Portal over MCP or the CLI bridge. The agent instructions of **Prepare Workspace** describe the format.
- **Import and export problems in PROBLEMS** — every object that an import from TIA Portal did not export, or exported with a warning (for example *Inconsistent blocks and PLC data types (UDT) cannot be exported.*), and every file that an export to TIA Portal did not write is now an entry in the PROBLEMS panel with TIA Portal's reason; for an object without a file, a click shows TIA Portal's whole message. The notification offers **Show Problems**, and an entry stays until its object is transferred again. The AI tools fill the same entries, and `tia_get_problems` returns them.

### Fixed

- **`tia_connect` over MCP and the CLI bridge waited for a click** — with several TIA Portal instances running, it now attaches to the instance that has the project named in `projectName`, or answers with the list of instances so the caller can name one. In Copilot Chat the instance picker still appears.
- **Long AI tool calls over MCP were given up by the client** — a running call now sends a progress notification every 20 seconds when the client asks for progress, so the client keeps waiting while TIA Portal works.
- **A project open in TIA Portal that the extension did not see** — **Connect** and **Select Project** found no project although TIA Portal showed it: TIA Portal Openness gives no access to a project that needs support packages (HSP, GSD files) or products not installed on the PC. The extension now says so and what to do — install what is missing (TIA Portal: **Options > Support packages**), restart TIA Portal, open the project and connect again — with **Open Help** and **Show Logs**; for a V21 project the message lists the support packages the project uses. The AI tools give the same reason.

## [4.5.0] - 2026-10-30

### Added

- **WinCC Unified screens as JSON files** (PRO) — **Import HMI Screens** and **Import All HMI Elements** write every WinCC Unified screen to `Screens/<screen groups>/<screen>.json`: its screen items with their properties, dynamizations and events (TIA Portal has no export format of its own for these screens). TIA Portal Openness does not say which screen items are grouped, so a screen with groups is not written; the tab **Screens with groups of screen items** lists such screens. Ungroup them in TIA Portal (Ctrl+A, **Ungroup**) and click **Import Again** — Ctrl+Z in TIA Portal restores the groups afterwards — or tick a screen to import it anyway. The import shows its progress and the time left; **Cancel** stops it after the current screen.
- **WinCC Unified script modules** (PRO, TIA Portal V19 or newer) — imported as `Scripts/<module>.hmi.yml` + `<module>.hmi.js` (TIA Portal's own format) and exported back.
- **WinCC Unified tags, alarms, logs, connections, lists and runtime settings** (PRO) — **Import All HMI Elements**, **Import HMI Tags** and **Import HMI Connections** write the tag tables, alarms, logs, connections and runtime settings as JSON files, and the text and graphic lists in TIA Portal's own format (system text lists: TIA Portal V20 or newer, graphic lists: V21 or newer). **Export HMI to TIA Portal** writes them back: an existing object is updated, a missing one created.
- **Classic WinCC in both directions** (PRO, Comfort / Advanced / Professional) — the import from TIA Portal also writes the screen management (templates, pop-up and slide-in screens, global screen, screen overview), the cycles, the text and graphic lists and the VB scripts as SimaticML. **Export HMI to TIA Portal** writes these files back, each into the folder of its file — except the global screen and the screen overview, which TIA Portal Openness can only read. Empty folders are kept in both directions.
- **Export HMI to TIA Portal** (PRO) — right-click an HMI file or folder in the Explorer to write it to the HMI device. As for blocks, **Check and Overwrite Differences** skips identical files, and after the export of a folder the deletion preview lists the HMI objects the folder no longer has — deleted only when you confirm. A WinCC Unified screen is replaced as a whole and loses its groups of screen items (an unchanged screen is skipped and keeps them; one Undo in TIA Portal brings the old screen back); a screen with dynamic widgets is updated in place and keeps them. A value TIA Portal refuses rolls back the whole screen or file, and the log lists every refused value.
- **Compile HMI** (FREE) — compiles the HMI software of an HMI device (Command Palette, project tree). Errors and warnings appear in OUTPUT and PROBLEMS — for WinCC Unified on the line of the screen item in the screen file. **Compile after Export** applies to the HMI export too.
- **AI tools and the HMI** — `tia_export_device`, `tia_import_file`, `tia_import_folder`, `tia_fix_compile_errors` and `tia_compile` (`target: "hmi"`) work with HMI devices too, so an AI agent can correct a screen until it compiles. WinCC Unified screens with groups of screen items are left out (the agent asks you to ungroup them), and HMI objects without a file are deleted only with `deleteOrphans: true`.
- **What's New** — after an update the extension opens the *What's New* tab once: the new functions and a video in which an AI agent builds a complete PLC and HMI project with this extension (the README shows it too). **CMsoft Import for TiaPortal: What's New** opens the tab again.

### Fixed

- **OBs exported from `.s7dcl` files became program cycle OBs** — TIA Portal imports every OB from an `.s7dcl` file as a program cycle OB, also in place of an existing one: a cyclic interrupt OB30 became a program cycle OB, and the compilation still succeeded. An `.s7dcl` file now never replaces an OB other than the program cycle OB 1 (the export stops with a message), and the import from TIA Portal writes such OBs as `.xml`, which keeps their type, number and cycle time. **Check the interrupt, startup and error OBs** of projects that received `.s7dcl` files from an earlier version (*Properties > General*: type, number, cycle time).
- **A file TIA Portal rejected deleted the block** — exporting an `.s7dcl` or `.xml` file deleted the existing block before TIA Portal checked the file, so one typo could remove a block. A rejected file now leaves the block in TIA Portal unchanged.
- **Check and Overwrite Differences rewrote inconsistent blocks** — a block TIA Portal could not export for the comparison (for example a caller of a function block that was just written) was written without a comparison, which could change the start information of an OB so that the PLC no longer compiled. Such a block is now compiled and compared first.
- **`tia_import_folder` moved blocks into a wrong group** — for a folder more than one level below `Program blocks`, the AI tool and the CLI bridge moved the blocks into a new group at the root. The whole group path is kept now.
- **Instance DBs recreated with a manual number** — an instance DB created again from its `.xml` keeps automatic numbering now, and inside a Software Unit its namespace (which caused compile errors and a second instance DB of the same name).
- **Technology objects in groups** — exporting a technology object of a user group failed with *object already exists*, and **Check and Overwrite Differences** never found one identical. Both work now; a new technology object goes to the group of its folder (TIA Portal V19 or newer).
- **HW Config of a device in a TIA device folder** — the device was not found, yet the import reported success. Such devices are found now, a failure is reported, and **Compare and skip identical** skips an unchanged device.
- **Tag tables as XML instead of Excel workbooks** ([#13](https://github.com/cmariusz/TiaImportExport.VSExt/issues/13)) — with **Format PLC Tags** set to *XLSX*, the imports of devices, of the project, of tag table groups and of Software Units wrote tag tables as `.xml` on some computers. They are always written as `.xlsx` now; the `.xml` of an earlier import is replaced at the next import.
- **Unchanged files written again** — importing again from TIA Portal rewrote unchanged tag table workbooks, `_unit.json` and CAx files, which showed up as changes in Git. They are written only when their content changes.
- **Project library types always as `.xml`** — library types are written like blocks now (SCL as `.scl`, LAD / FBD / STL as `.s7dcl` + `.s7res`, PLC data types as `.udt`); a type written as XML says why.
- **WinCC Unified tag tables and connections missing** — tag tables with PLC tags were not written and the connections not imported. Every tag table is written as JSON now (older `.hmi.yml` files can still be exported to TIA Portal), the connections to `Connections/Connections.json`.
- **Classic WinCC imported again** — a second import of the screens, tag tables or connections of a classic WinCC device failed for every existing file; the files are replaced now.
- **Imports from TIA Portal with failed items** — **Import All HMI Elements** reported success although screens had failed. An import with failed items now shows a warning with their number and the first reason.
- **Export commands on TIA device folders** — the Explorer offered **Export to TIA - Program and HW**, **Export to TIA - Program without HW** and **Export to TIA Portal: HW Config Folder** on a TIA device folder instead of on the PLC folder inside it. They are on the device folders now.
- **Long MCP tool calls lost their answer** — MCP clients gave up after 5 minutes (*fetch failed*) while TIA Portal was still working, for example on an HMI export with many screens. The answer is an event stream now (`text/event-stream`) with a keep-alive every 15 seconds; your own scripts read the JSON message from its `data:` line.
- **AI tools** — `tia_export_project` counts and names the objects TIA Portal refused to export; `tia_list_blocks`, `tia_list_devices` and the export tools no longer list blocks an import has deleted; `tia_select_project` with the name of no open project keeps the selected project; the answers report skipped identical files and how many files were imported, skipped and failed; and every license refusal of the AI tools and the CLI bridge says how to get PRO.
- **Log flooded during exports** — *Device folders for the Explorer menus* is no longer logged every second or two.
- **Refresh license status with an active license** — it asked to accept the license terms first in some VS Code profiles; it now renews the key and reports the license as up to date.
- **User manual: Import Entire Project** — the manual said it imports the hardware too. It imports the programs of every device; the hardware comes with **Import HW Configuration**, the HMI with **Import All HMI Elements**.

### Changed

- **Export Blocks to TIA asks less** — files in the folder of a PLC go to that PLC without asking; the Software Unit question comes only when the PLC has Software Units or the files lie below `Units/<Unit>/`.
- **Import confirmations are dialogs** — **Import Entire Project**, **Import Project Library Types** and **Import Languages & Project Texts** ask in a dialog instead of a notification that could be missed.
- **Safer defaults in the export dialogs** — the deletion preview defaults to **Keep in TIA Portal** (Enter no longer deletes), and **Export Blocks to TIA** offers **Check and Overwrite Differences** first.

### Removed

- The setting `tiaImport.preserveTimestamps` — it had no effect.

- **Purchase wording** — PRO is sold as a monthly or yearly subscription that renews automatically until cancelled.

### Fixed

- **Hardware configuration in FREE** — the HW Config imports asked for their options and then failed for every device; they now show the license dialog first.
- **Project texts imported again** — a second **Import Languages & Project Texts** failed; the workbook is replaced now.

- **Compare and skip identical with AutomationML** — an unchanged `.aml` file is skipped now, like an `.xml` file.
- **License messages for AI agents and scripts** — a PRO function in FREE answered with the bare code `LICENSE_REQUIRED`; the answer now says what is missing and how to activate a license.
- **CLI Bridge row in FREE** — shows `On (PRO)`, since the CLI bridge needs PRO.
- **Project tree** — an HMI device no longer offers PLC commands, and the commands of tree nodes are no longer in the Command Palette.

## [4.1.0] - 2026-10-17

### Added

- **The user manual inside the extension** — **CMsoft Import for TiaPortal: Open User Manual** shows the manual in VS Code, offline; **Search the User Manual** opens a chapter or section. The manual also opens from the *Get Started* walkthrough, the empty **Project Structure** view and **Open Help** after a failed connection. **Help: CMsoft Manuals…** and the **CMsoft** status bar item list the manuals of all installed CMsoft extensions.
- **Preview before anything is deleted in TIA Portal** — the exports to TIA Portal list the TIA objects missing in the workspace first and delete them only after **Delete in TIA Portal**.
- **Audit log of deletions** — every deletion in TIA Portal is recorded in `<workspace>/.tia/audit.log`.
- **Reinitializing data blocks during a PLC download** — when a download needs to reinitialize data blocks (the PLC stops and their values, retain data included, are reset to the start values), the row **DB Reinit on Download** of the **Connection** view (setting `tiaImport.lmTools.reinitializeDataBlocks`) decides: **Never**, **Ask** (default) or **Always**. *Ask* asks you in VS Code, never the AI model. Before, such a download always failed.
- **A failed connection says why** — when **Connect** cannot attach to TIA Portal (TIA Portal Openness not installed, user not in the *Siemens TIA Openness* group, …), a message shows the reason with **Open Help** and **Show Logs**.
- **License panel** — in English; with an active license it shows *Your license* with **Extend license** and **Cancel subscription**. When buying you choose a monthly or yearly subscription that renews automatically and enter the company and country for the license. Every purchase has a 14-day money-back guarantee, and each license covers one computer ([Terms of Sale](TERMS.md)). The **CMsoft** status bar item replaces *TIA: PRO / FREE* and lists the licenses of all installed CMsoft extensions.
- **Prepare Workspace next to other CMsoft extensions** — the agent instructions are in files named after the extension, and `AGENTS.md`, `CLAUDE.md`, `.github/copilot-instructions.md`, `.gitignore` and `Tools/README.md` get a section of their own, so one workspace can hold the instructions of several CMsoft extensions. Running it again updates only that section and those files; your own text stays.
- **`tiaImport.lmTools.allowOutputOutsideWorkspace`** — the AI tools write exports only into the open workspace folders unless this setting allows other folders.

### Changed

- **New name: CMsoft Import for TiaPortal** — formerly *TIA Portal Import*. The commands, views, the Output channel, the walkthrough, the chat participant (still `@tia`) and the MCP server carry the new name; the extension ID, the settings and the files it writes stay the same. The companion extensions are now *CMsoft Viewer for TiaPortal* (formerly TIA Viewer) and *CMsoft Import for Step7* (formerly Step7 Import/Export).
- **New icons**.
- **Agents delete nothing unless asked** — `tia_import_folder` and `tia_import_unit` keep TIA objects without a local file unless the call says `deleteOrphans: true` (`tia_import_unit` deleted them by default before), and then they always ask.
- **One TIA Portal operation at a time** — the commands, Copilot, `@tia`, MCP and the CLI bridge wait for a running operation instead of running in parallel; a busy TIA Portal is reported as busy, not as lost.
- **Native module repair asks first** — when the native module does not load in a new VS Code version, the extension asks before it downloads the matching package from npm.
- **`tia_export_hw_config` without `includeSubnets`** — the option never had an effect.
- **The CMsoft shop has its own address** — <https://shop.cmsoft.com.pl>.
- **Disclaimer of liability** — the user manual and the README sum up the disclaimer of the End User License Agreement, and the *Get Started* walkthrough has a step **Work safely**: imports, exports and PLC downloads are at your own risk, and code written by an AI assistant is not reviewed or verified by CMsoft. `@tia` and the instructions of **Prepare Workspace** tell assistants to leave safety programs alone unless you confirm an independent review. The terms of the documents are unchanged.

### Removed

- The setting `tiaImport.license.deliveryMode` — the license panel offers the ways to buy directly.

### Fixed

- **A source with an error was imported as an empty block** — an `.scl`, `.db` or `.udt` file with a syntax error (for example a member named `Counter`) was reported as imported while TIA Portal created the data block or data type empty — also in place of an existing one. The export of such a file now fails with TIA Portal's message and line, and TIA Portal stays unchanged. Errors in the code of an FB, FC or OB still import the block and show up when compiling.
- **Importing a block file deleted an unrelated block** — a file such as `Pump_Station_DB.db` whose block did not exist yet could be taken for the block `Pump_Station`, which was deleted. The target is now only the block named like the file or named inside it.
- **The export to TIA Portal could delete blocks that still existed in the workspace** — for example a block whose file name has a number suffix, or every object of a group whose folder was empty or could not be read. Fixed; know-how protected and system blocks are never deleted.
- **`overwriteExisting: false` still overwrote changed objects** — it now leaves every object that exists in TIA Portal unchanged and only creates the missing ones.
- **Check and overwrite differences stopped at a LAD block** — the export of `Main.scl` failed for the LAD `Main [OB1]` of every new project. A block in LAD, FBD, GRAPH, CFC or SFC now counts as different and is replaced; know-how protected and fail-safe blocks are kept and reported.
- **Software Units** — the export of a unit no longer fails without a reason when the unit has an empty `PLC data types` folder or tag tables as `.xlsx`, the `.xlsx` tag tables of a unit reach TIA Portal now, and a folder named "Units" elsewhere is no longer taken for a Software Unit.
- **Unchanged `.xlsx` tag tables rewritten on every export** — unchanged tables are skipped now, and a Software Unit table keeps its *Published* state.
- **`@tia` ran no tools** — the chat participant now runs the tools the model calls, with the confirmations in the chat, and offers every TIA tool.
- **A busy TIA Portal was reported as a lost connection** — after a long project load, or while TIA Portal showed a dialog, operations failed and the extension even disconnected. The connection check now waits up to 30 seconds and disconnects only when the session is really gone; `tia_connect` then reconnects.
- **AI tools** — every TIA tool says in the chat what it does (for example *Export block "Main" of "PLC1"*) instead of showing its raw input; failed imports name the failing items; `tiaImport.lmTools.maxFixIterations` limits `tia_fix_compile_errors` in Copilot too; device and project exports over MCP and the CLI no longer wait for a question nobody sees; and `tia_export_cross_references` writes to the device export folder.
- **Compile errors of PLCs in TIA device folders did not reach PROBLEMS** — fixed.
- **Cross-reference export wrote empty records** — every line of `cross-references.jsonl` was `{}`; export the cross-references again to replace such files.
- **WinCC Unified export failed for screens and tag tables inside groups** — fixed.
- **The rows of the Connection view did not follow the Settings editor** — they update at once now.
- **The *Get Started* walkthrough was never shown** — it is now.
- **Messages** — a missing component for the selected TIA Portal version names the version instead of saying *edge-js is required*, and groups TIA Portal could not read are reported as warnings instead of vanishing from the tree.
- **Local servers (MCP, CLI bridge)** — requests from web pages or with a foreign `Host` header are refused (DNS rebinding), request bodies are limited to 10 MB, idle MCP sessions are closed after 30 minutes, and the `.tia` folder gets a `.gitignore` so session tokens are never committed.
- **Documentation without Node.js** — the README no longer lists Node.js and the .NET 8 runtime as requirements: the extension runs on the .NET Framework 4.8 of Windows and the runtime of VS Code. The CLI examples call the bridge from PowerShell or with the `tia` function of the user manual.
